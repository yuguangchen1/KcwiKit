# Command Line Tools

Here is a list of command line tools offered by this package, and their functionalities. 

## kcrm_create_crmsk

```bash
kcrm_create_crmsk filename [-l [LABEL [LABEL ...]]] [-s SIGMA] [--ratio RATIO] [--proc PROC] [--base_dir BASE_DIR] [--redux_dir REDUX_DIR] 
```
This script runs the median cosmic ray rejection and creates the FITS CR masks (`<frame>_crmsk.fits`) for each frame.
- `filename` - the input `json` file containing the grouping of frames generated by the `kcrm_group_frames` script. 
- `-l --label` - one or multiple label names in the grouping `json` file of which the CR masks are created. If no label is specified, all labels are created. 
- `-s --sigma` - sigma-clipping threshold on the frame minus the group median (default 3). Raise it for bright continuum or emission-line sources.
- `--ratio` - a pixel must also exceed this relative excess, |frame - median| / median (default 0.6).
- `--proc` - processing table used to find the wavelength map (default `kcwir.proc` under `base_dir`).
- `--base_dir` - directory to which the raw frames are stored. Default is `./`.
- `--redux_dir` - diretory to which the redux directory is created by the DRP. Default is `./redux`.

## kcrm_group_frames

```bash
kcrm_group_frames logfile outfile [-c] [-d] [-i] [--redux_dir REDUX_DIR]
```
This script groups the individual frames based on the target names, PA, instrument setup, and exposure times. This grouping is stored in a `json` file to be used for cosmic ray rejction. 
- `logfile` - the `csv` file generated by `kcwi_gen_log`, containing the header information for all the frames. 
- `outfile` - the file name of the output `json` file. 
- `-c --continuous` - split non-continuous files into seperate groups. 
- `-d --display` - print out the grouping.
- `-i --int` - check if the `*_int.fits` exists in the `redux` directory
- `--redux_dir` - location of the redux directory created by the DRP. Default is `./redux`

## kcwi_collapse

```bash
kcwi_collapse file [file ...] [--wavebin WAVEBIN WAVEBIN] [--usepix]
```
Create white-light image from data cube(s). 
- `file` - file name(s) to be acted on. 
- `--wavebin` - the lower and upper wavelength limits in Angstrom.
- `--usepix` - change the unit of the previous `wavebin` parameter to pixel index. 

## kcwi_combinestd

```bash
kcwi_combinestd listfile [--noplot]
```
Combining a series of inverse sensitivity curves generated from multiple standard stars or standard star exposures. Often used to achieve higher accuracy (~3.5%) in flux calibration. 
- `listfile` - an ASCII list containing the absolute path and the full file names of the `invsens` files generated by the DRP or `KSkyWizard`. 
- `--noplot` - avoid creating the bokeh figure. 

## kcwi_flatten_cube

```bash
kcwi_flatten_cube file [file ...] [-r] [-m] [-t]
```
Flatten or de-flatten a FITS cube. Created from `kcwi_flatten_cube.pro` in the IDL DRP.
- `file` - file name(s) of the FITS cubes. 
- `-r --reverse` - reverse the flattening, i.e., building a cube from the 2D flattened image
- `-m --mask` - conduct the flattening or deflattening on a mask cube. 
- `-t --trim` - the amount pixels to be trimmed on top and bottom of the cube. 

## kcwi_gen_log
```bash
kcwi_gen_log outfile -f [FILENAME [FILENAME ...]] [-r] [-b] [-d]
```
Generate a `csv` file containing the important header information of FITS files. 
- `outfile` - name of the output file
- '-f --filename' - name(s) of the FITS files
- '-r --RED' - only perform on the red channel data
- '-b --BLUE' - only perform on the blue channel data
- '-d --display' - print the table

## kcwi_makemask
```bash
kcwi_makemask [dir]
```
Generate FITS masks from then DS9 region files for sky subtraction. This script is a wrapper for `kcwi_masksky_ds9`. 
- `dir` - diretory of which all `*.reg` will be converted. Default is `./`.

## kcwi_makemask_medfilter
```bash
kcwi_makemask_medfilter [dir] [-d]
```
Generate FITS masks from then DS9 region files for median filtering only. This script is a wrapper for `kcwi_masksky_ds9_thum` and `kcwi_masksky_ds9_2d`. 
- `dir` - diretory of which all `*.thum.reg` and `*_icube_2d.reg` will be converted. Default is `./`.
- `-d --cubed` - act on `cubed` files. 

## kcwi_masksky_ds9_2d
```bash
kcwi_masksky_ds9_2d [imagename] [regionname]
```
Generate median filter masks from region files for the flatten cube. 
- `imagename` - name of the `_2d.fits` file generated by `kcwi_flatten_cube`.
- `regionname` - name of the `region` file created from `ds9`.

## kcwi_masksky_ds9_thum
```bash
kcwi_masksky_ds9_thum [imagename] [regionname]
```
Generate median filter masks from region files for the white light image. 
- `imagename` - name of the `_thum.fits` file generated by `kcwi_collapse`.
- `regionname` - name of the `region` file created from `ds9`.

## kcwi_masksky_ds9_zap
```bash
kcwi_masksky_ds9_zap [imagename] [regionname]
```
Generate binary mask for KSkyWizard.
- `imagename` - name of the `_wlimg.fits` generated by KSkyWizard.
- `regionname` - name of the `region` file created from `ds9` (optional if named as `<prefix>_<image number>.reg`).

## kcwi_masksky_ds9
```bash
kcwi_masksky_ds9 [imagename] [regionname]
```
Generate binary masks for DRP sky subtraction from region files. This is copied from the offical DRP. 
- `imagename` - name of the FITS file. They can be `*_intf.fits` or `*_intk.fits`.
- `regionname` - name of the `region` file created from `ds9`.

## kcwi_medfilter
```bash
kcwi_medfilter file [file ...] [-p PARFN] [--zbin ZBIN] [--ybin YBIN] [--ytrim YTRIM] [--override] [--nproc NPROC]
```
Conduct median filtering and subtract the median-filtered background. 
- `file` - file name(s) of the frame(s) to be subtracted. 
- `-p --par` - name of the parameter file (see below for setting up this file).  
- `--zbin` - window size in the z-direction. 
- `--ybin` - window size in the y-direction. 
- `--ytrim` - number of pixels to be trimmed on the edge. 
- `--override` - act on processed file. 
- `--nproc` - number of processors for parallelization.

<details>
<summary> Setting up the parameter file.  </summary>

Using default parameters do not require to set up a parameter file. However, if you prefer to modify certain parameters for single files, but still wish to run the files in batch, you may set up a parameter file. Below is an example with the default parameters.
```
FN = kb200616_00053     # file name prefix
ZBIN = 100              # binning size (pixel) in the wavelength direction
YBIN = 16               # binning size (pixel) in the y direction
YTRIM = 4               # number of pixels to trim on the top and bottom of the slicer 
BKGTYPE = 0             # set 1 to skip this frame 
```
Additional frames can be appended below. 

</details>




## kcwi_dichroic_step
```bash
kcwi_dichroic_step base [--red RED] [--width WIDTH] [--gapoff GAPOFF] [--suffix SUFFIX] [--plot PLOT]
```
Model-free check for an additive (sky-level) mismatch between the blue and red stacks at the dichroic. Per spaxel it fits `F_blue_end = k F_red_start + c`; `c = 0` means no additive mismatch, `c > 0` means blue is high / red low in faint regions.
- `base` - blue stack base name (reads `<base>_icubes_wcs.fits`, falls back to `<base>_icubes.fits`, plus the `_mcubes` / `_vcubes` if present). Both stacks must be on the same grid.
- `--red` - red stack base name (default `<base>-red`), e.g. the unchanged red stack after `kcwi_skylevel` corrected only blue.
- `--width` - window width on each side of the gap [Å observed] (default 150).
- `--gapoff` - stay this far inside WAVGOOD [Å] (default 20).
- `--suffix` - flux cube suffix (default `_wcs`).
- `--plot` - write a PNG of F_blue vs F_red and F_blue/F_red vs brightness.

## kcwi_skylevel
```bash
kcwi_skylevel measure BLUE.list RED.list [--fixed red|blue|none] [--same] [--groups auto|FILE] [--template sky|flat|counts] [--image FILE,LO,HI,UNIT[,PIVOT]] [--cubewin NPZ] [--width WIDTH] [--fwhm FWHM] [--json JSON] [--path-map FROM=TO]
kcwi_skylevel apply   BLUE.list RED.list [--json JSON] [--suffix _skl] [--outdir DIR] [--stack] [--dry-run] [--path-map FROM=TO]
```
Measure and correct the residual sky level of each channel, modelled per channel as `beta x T(lambda)`, with `T` the continuum of the sky that was subtracted from each frame. `T` is taken from the frame's own extensions: `SKYMODEL_ZAP` (KSkyWizard), `SKY` / `SKYMODEL`, or `NOSKYSUB - data` (KCWI_DRP). `beta > 0`: too much sky subtracted; `beta < 0`: too little. Run in the stack folder.
- `measure` - solve for `beta_blue`, `beta_red` from the dichroic continuity of the current stacks, plus optional absolute anchors; prints every constraint with its residual and writes `<blue base>.skylevel.json`.
- `apply` - for each corrected channel, write `<frame>_skl_icubes.fits` (all extensions kept; header `SKLBETA`, `SKLTEMPL`) and `<base>_skl.list` (or `<base>_skl-red.list`) with copies of its `.par`, `.shift.list`, `.preshift.list`, `.flx.list`, `.astrom.list`; restack it as usual. The fixed channel is not touched: keep its original list and stack. `--stack` corrects the existing stack directly instead (quick check, no restack). Zero (no-data) voxels are left at zero.
- `--fixed` - channel kept as it is: `red` (default; solve for `beta_blue`), `blue` (solve for `beta_red`), or `none` (solve for both; needs at least one anchor). The dichroic constraint alone fixes only the difference between the channels.
- `--same` - one beta for both channels (both used the same sky pointing); overrides `--fixed`.
- `--groups` - one beta per group of frames instead of one per channel, measured from the frames themselves: a blue frame and the red frames taken at the same pointing and PA. `auto` groups by RA, Dec (1") and PA (0.5 deg); `FILE` lists one group per line (frame names, e.g. `kb250503_00098 kr250503_00116 kr250503_00117 kr250503_00118`). For data where the sky changed between exposures (e.g. near twilight). Needs `--fixed red|blue` or `--same`; anchors are not used. `apply` then corrects each frame with its group's beta (frame mode only; `--stack` is refused).
- `--template` - shape of the error: `sky` (default), `flat` (constant in flux) or `counts` (constant in detector counts).
- `--image` - reference image anchor `KCWI = a x ref + b` in the KCWI window `LO-HI` [Å observed]; the scale `a` is free, so only the zero level of the reference matters. `UNIT`: `hst` (PHOTFLAM), `nmgy` (needs `PIVOT`), `ps1` (Pan-STARRS stack cutout, needs `PIVOT`: g 4866, r 6215, i 7545), `flam`.
- `--cubewin` - anchors from another IFU cube, collapsed with `kcwi_cube_windows`.
- `--path-map` - rewrite frame paths in the lists (e.g. `/Volumes/X=/mnt/X`).

- `--template-step` - sample the sky extension every this many Å when building the template (default 2; it is smoothed over 60 Å anyway; 0 = every plane).

Many sources at once:
```bash
kcwi_skylevel batch SOURCES [--steps measure|apply|measure,apply] [--jobs N] [common options]
```
`SOURCES` has one source per line (`#` comments): a stack base name (lists `NAME.list` and `NAME-red.list`) or two list files, optionally followed by options for that source only, which override the common ones:
```
IRAS03582+6012
LEDA66688-final       --groups auto
UGC2369S              --same
```
Each source writes its usual `.skylevel.json` and its full output to `<NAME>.skylevel.log`; a summary table (mode, betas, dichroic c, warnings, status) is printed at the end, and a failing source does not stop the others. `--jobs N` runs N sources in parallel processes.

Check the result with `kcwi_dichroic_step <base>_skl --red <base>-red` (`c ~ 0`; drop `--red` if red was corrected too). `apply` prints the exact command.

## kcwi_cube_windows
```bash
kcwi_cube_windows cube out.npz --win LO HI [--win LO HI ...] [--ext EXT]
```
Collapse a (large) IFU cube, e.g. MUSE, into median images in wavelength windows (strong sky lines left out), per arcsec², with the celestial WCS, written to an `.npz` for `kcwi_skylevel --cubewin`. Reads the cube in chunks; run it where the cube lives rather than over a network mount.
- `--win` - window `LO HI` [Å observed]; repeat for several windows.
- `--ext` - data extension (default `DATA` if present, else 0).

## kcwi_xalign
```bash
kcwi_xalign shifts BLUE.list RED.list --z Z [--ref image.fits | --astrom T.astrom.list]
kcwi_xalign wcs    BLUE.list RED.list --z Z [--overwrite] [--check-only]
kcwi_xalign wcs    NAME --suffix-blue _skl              # = NAME_skl.list and NAME-red.list
kcwi_xalign batch  SOURCES [--steps shifts,stack,wcs] [--suffix-blue S] [--suffix-red S] [--channels blue|red|both] [--stack-kw K=V,...] [common options]
```
Aligns every blue and red frame to one sky frame by cross-correlation (`shifts` writes both `.shift.list` files), and after stacking checks the two stacks against each other and writes `<stack>_icubes_wcs.fits` (`wcs`).
- A source name instead of two lists uses `NAME<suffix-blue>.list` and `NAME<suffix-red>-red.list`.
- `batch`: `SOURCES` has one source per line (`#` comments), a name or two list files, followed by options for that source only (e.g. its `--z`, `--ref`). Steps run in the order shifts, stack, wcs; `stack` calls `kcwi_stack` on `--channels` with `--stack-kw` (default `crr_split=True,crr_split_mode=frame,crr_save_mask=True,overwrite=True`). Each source logs to `<NAME>.xalign.log`; a summary (same grid?, red-vs-blue offset, warnings, status) is printed at the end.
- After `kcwi_skylevel apply` corrected one channel, do not re-run `shifts` (it would rewrite the unchanged channel's shift list; `apply` already copied the shifts). Restack the corrected channel and check: `kcwi_xalign batch SOURCES --steps stack,wcs --suffix-blue _skl --channels blue --overwrite`.

## kcwi_automask
```bash
kcwi_automask [images ...] [-j JSON [-a]] [-t | -b | -w] [-c [--regfrom REG]] [--no-clobber] [-p] [-s] [-n NSIG] [-g GROW] [--maxfrac F] [--shape polygon|ellipse] [...]
```
Makes the masks that are otherwise drawn by hand in DS9, and writes them as DS9 region files following the names `kcwi_makemask` / `kcwi_makemask_medfilter` expect, so they can be checked and edited before conversion. Four modes:
- default (`<base>_intf.fits` -> `<base>.reg` -> `<base>_smsk.fits`): sky mask for the DRP; continuum traces are found slice by slice and the masked width follows the brightness with wavelength (`--rect` for plain rectangles).
- `-t --thum` (`<base>_icube.thum.fits` -> `.thum.reg` -> `.mask.fits`): mask for median filtering; per-slice budget `--maxfrac` (default 0.4) and `--edge` keep the filter well behaved.
- `-b --bcrmsk` (`<base>_intf.fits` -> `<base>_bcrmsk.reg` and `<base>_intf_bcrmsk.fits`): astroscrappy protection mask for the DRP (`bcrmsk = True` in `kcwi.cfg`); masks the bright spots themselves (`--bcr-mode spots`, threshold `--bcr-thresh` counts) or full-height strips.
- `-w --wl` (`<base>_wlimg.fits` -> `<base>.reg` -> `<base>_zap_mask.fits`): source mask for KSkyWizard/ZAP, ellipses in physical coordinates.
- `-j --json` - take the frames from a grouping JSON (first frame of each group; `-a --all` for every frame).
- `-c --convert` - do not detect anything; build the mask FITS from the existing region file (use after hand-editing in DS9). `--regfrom REG` takes the regions from that file for every image given.
- `--no-clobber` - never overwrite an existing region file. `-p --plot` - quick-look PNG per frame. `-s --smsk` - also write the mask FITS directly.
- Detection parameters (`-n --nsig`, `-g --grow`, `--grow-nsig`, `--maxfrac`, `--minpix`, `--edge`, `--max-radius`, `--shape`, `--ybin`, `--wing-nsig`, `--seed-nsig`, `--bright-nsig`, `--bright-reach`, `--bkg-window`, `--edge-trim`) have mode-dependent defaults listed in `kcwi_automask -h`; the module docstring explains the algorithm of each mode.

## kcwi_masksky_ds9_bcrr
```bash
kcwi_masksky_ds9_bcrr imagename regionname
```
Converts a DS9 region file drawn on a `*_intf.fits` frame into an astroscrappy *protection* mask `<frame>_intf_bcrmsk.fits` (1 = do not clean). The KCWI_DRP fork hands it to astroscrappy as `inmask` when `bcrmsk = True` is set in `kcwi.cfg`. `kcwi_automask --bcrmsk` produces the same files automatically.

## kcwi_mask_cube
```bash
kcwi_mask_cube files [files ...] (-r | -b)
```
Sets bit 32 of the `FLAGS` extension inside the regions of `<frame>_rm.reg`, for every wavelength channel, so those pixels are dropped from the final stack. A copy of the cube is written; the original is untouched.
- `files` - region file name(s), must end with `_rm.reg`.
- `-r --red` - apply to `<frame>_zap_icubes.fits` -> `<frame>_zap_new_icubes.fits`.
- `-b --blue` - apply to `<frame>_icubes.fits` -> `<frame>_new_icubes.fits`.

## kcwi_gen_skyfile
```bash
kcwi_gen_skyfile outfile -l REFERENCELOG [-d]
```
Builds the DRP sky-frame table (`kcwi.sky`) from the frame-grouping JSON of `kcrm_group_frames`: a group `<obj>` with a companion group `<obj>_sky` uses the first frame of `<obj>_sky` as external sky frame (no sky mask); otherwise each frame is its own sky frame with the group's first-frame `_smsk.fits` mask.
- `outfile` - output table, usually `kcwi.sky` in the working directory.
- `-l --referencelog` - the grouping JSON.
- `-d --display` - print the table.

## kcwi_shiftcheck
```bash
kcwi_shiftcheck BLUE.list [RED.list] [--a .shift.list] [--b OTHER] [--z Z] [--radius R] [--tol MAS] [--plot PNG]
```
How good is a `.shift.list`? Every frame is placed on the sky exactly as `kcwi_stack` would (preshift on `CRVAL`, `CRPIX += shift`) and compared with the average of the other frames; prints the residual offset and R^2 per frame, the blue-vs-red offset when two lists are given, and the frame-by-frame difference between two shift sets (`--a`, `--b`: suffixes replacing `.list`, or file names). Nothing is fitted to either list, so a `kcwi_align` or hand-made list can be compared with a `kcwi_xalign` one on equal terms.
